# 佑康・绿通卡 · 本期交互原型

入口：`youkang.html`（用户端）、`admin-youkang.html`（后台）、`nurse-youkang.html`（陪护端）。原首页、我的、卡包、订单及后台导航已接入入口；服务目录新增“体检服务”。

本期只有1698元固定套餐：体检1333元、陪同299元、绿通代约66元。不含额外加项。医院固定为西安交通大学第一附属医院体检中心。男女项目各16项，保留提供的单价；项目参考价合计分别为1335.5元、1325.5元，与套餐基础价分开。检查意义由后台录入医院确认的说明，未录入前前端提示以体检中心说明为准。

支付成功发卡并标VIP；付费卡、免费奖励卡发放后有效期2年。购买时保存项目快照，后续配置不会改写已有订单。奖励卡保存发卡时项目快照。

流程：购买（原型模拟支付）→我的卡→预约→后台分配已认证在岗陪诊员→陪护端开始服务→服务中提交记录→客户出示6位核销码→陪诊员填写完成说明并核销→已完成。未预约不能分配；非本人分配订单不能操作；已使用/已预约/过期卡不能再次预约。

奖励仅一级直推，A需先付费成为VIP。A的直推客户付费购卡且体检核销完成后计数，每位客户只计一次。每满3位，自动发1张同权益免费卡；6位发2张，可循环。二级及以下、未完成订单、重复客户和免费卡订单均不计数。既有推荐关系保留，禁止自推、循环关系和购买后补绑；重复支付/核销不会重复发卡。

分享页有专属推广链接、真实QR码和750×1120 PNG海报下载。使用本地file地址时，需发布到可访问域名后再对外扫码。未发布的本地链接仅用于演示。

后台“原型账号预览”可创建新的演示客户、填写一级推广码，并切换账号验证多轮推荐。护理员身份沿用原认证流程。所有原型数据使用当前浏览器本地存储；支付、医院排期、跨设备好友数据同步、账户权限校验需正式服务端与小程序支付接入，当前未产生真实支付或医院预约。

验证：`node tests/youkang.test.cjs`、`node tests/youkang-ui.test.cjs`、`node tests/nurse-workflow.test.cjs`。

## 购卡表单
点击购买先进入确认购卡页，选择男/女套餐；可从现有就诊人档案带入姓名、身份证号和年龄，手机号缺失时补填。姓名、身份证号、手机号、年龄必填，保存意向体检日期。意向日期不是确认预约，不触发后台派单。支付后信息同步到服务订单，供绿通专员对接；保留原卡包正式预约和陪护服务流转。不提供额外加项需求。

## 卡包与详情结构
卡包按「助浴卡 / 绿通卡」分栏，互相独立显示，保留原有兑换和预约入口。绿通卡相关入口默认打开绿通卡标签。详情参考现有服务商品页，按主图、服务信息、服务详情、体检项目、购买须知排列；移除推荐好友模块。服务约定固定在底部按钮上方，支持弹窗查看全文，购卡表单沿用同一勾选状态。

详情页三部分已合并到一张卡片，移除章节切换；推广页移除顶部套餐/推广奖励切换和我的入口。用户「我的」菜单新增「我的推广」，进入推广奖励页并可返回我的。

## 表单统一
购卡确认页复用现有服务下单的 ui/checkout-design.css 卡片、选项和行输入样式；体检人改用同款底部档案选择弹层，主表单不再展示姓名/身份证/年龄输入，只输入一个联系人电话。订单从选中就诊人档案读取身份信息，不信任表单传入的姓名、身份证或年龄。套餐和意向日期继续保留；管理就诊人时暂存本次表单，返回后可继续填写。

## 绿通卡订单与预约返回
体检订单复用服务订单卡片的标题、服务对象、地点、价格、时间与人员区域；待预约订单提供「预约」按钮。来源列表的地址及筛选状态随预约链接传递，预约成功后刷新返回来源；从订单详情发起预约统一返回服务订单列表。卡包发起预约则返回绿通卡标签。预约页顶部返回也遵循同一路径。已通过数据/页面回归检查，并在浏览器实际验证订单列表、订单详情及卡包三条预约返回路径。

购物车确认订单弹窗已调整层级，高于底部导航；商品内容内部滚动，支付按钮与知情同意书保留在底部可见区域。地址选择弹层继续覆盖确认订单层。浏览器已检查按钮实际点击命中不被导航截获。
